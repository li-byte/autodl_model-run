# Skill: `reinforcement_learning/module`（SFT + GRPO 两阶段 LoRA 微调）

## 目标

这个目录实现了一个“先监督微调（SFT），再用 GRPO 做强化学习式对齐”的两阶段训练流水线，面向数学/推理类数据，核心目标是让模型稳定输出带有推理与答案分隔标记的格式，并在 GRPO 阶段用奖励函数同时约束“格式正确”和“答案正确”。

## 目录入口与职责划分

- `main.py`
  - 训练编排入口：初始化模型/Tokenizer，配置 SwanLab 回调，按开关依次执行 `SFT -> 保存 LoRA ->（清缓存）-> GRPO -> 保存 LoRA`。
  - 当前代码里对数据集只取了 `select(range(5))`（更像是调试/最小跑通用设置）。
- `config.py`
  - 训练常量与输出标记定义：`MAX_SEQ_LENGTH`、`LORA_RANK`、`SEED`、`GPU_MEMORY_UTILIZATION`、以及推理/答案的起止标记与 `SYSTEM_PROMPT`。
  - 同时写入了若干环境变量（HF 镜像、HF Transfer 开关、SwanLab Key）。
- `model_utils.py`
  - `init_model(checkpoint_path=None)`：用 Unsloth 的 `FastLanguageModel.from_pretrained` 加载基础模型，并用 `get_peft_model` 注入 LoRA；可选从 `checkpoint_path` 加载已有 LoRA 权重实现增量训练。
- `dataset_utils.py`
  - `format_sft_dataset(dataset, tokenizer)`：把 COT 数据整理成 chat-template 文本（`system/user/assistant` 三段消息），并将推理/答案包进 `config.py` 定义的标记中，生成 `text` 字段供 `SFTTrainer` 训练。
  - `format_grpo_dataset(dataset, tokenizer)`：把强化学习数据映射成 `prompt`（system+user 的消息列表）与 `answer`（真值答案）两列，供 `GRPOTrainer` 与奖励函数使用。
- `train_sft.py`
  - `train_sft(...)`：基于 `trl.SFTTrainer` / `SFTConfig` 做监督微调。
- `train_grpo.py`
  - `train_grpo(...)`：基于 `trl.GRPOTrainer` / `GRPOConfig` 做 GRPO 训练，并通过 vLLM `SamplingParams` 控制生成。
  - 奖励函数：
    - `match_format_approximately(completions)`：检查输出里是否包含 `<结束推理>`、`<答案>`、`<答案结束>` 等标记（存在则加分，否则扣分）。
    - `check_answer(completions, answer)`：用正则抽取答案区间，对比真值答案，匹配加分，不匹配扣分，格式缺失额外扣分。
- `架构设计.md`
  - 给出了训练流程与模块分层的文字版示意图，适合作为整体理解入口。

## 核心数据约定（非常重要）

### 1) SFT 数据（`format_sft_dataset`）

输入样本期望包含字段：

- `problem`
- `generated_solution`（其中会去掉 `<think>...</think>`）
- `expected_answer`

输出变成：

- `Messages`: `[{role: system}, {role: user}, {role: assistant}]`
- `text`: `tokenizer.apply_chat_template(Messages, tokenize=False)` 的结果

注意点：

- 代码会对 `expected_answer` 做“可转成数字”的过滤（`pd.to_numeric(..., errors="coerce")`），非数值答案会被丢弃。
- assistant 内容会拼成：
  - `REASONING_START + thoughts + REASONING_END + SOLUTION_START + expected_answer + SOLUTION_END`

### 2) GRPO 数据（`format_grpo_dataset`）

输入样本期望包含字段：

- `prompt`
- `solution`（作为真值答案）

输出变成：

- `prompt`: `[{role: system, content: SYSTEM_PROMPT}, {role: user, content: prompt}]`
- `answer`: `solution`

## 模型与 LoRA 初始化（`init_model`）

- 基础模型路径写死为相对路径：`../../../models/Qwen3-4B`
- LoRA 关键参数来自 `config.py`：`LORA_RANK`、`MAX_SEQ_LENGTH`、`GPU_MEMORY_UTILIZATION`、`SEED`
- LoRA target modules：`q_proj/k_proj/v_proj/o_proj/gate_proj/up_proj/down_proj`
- 传入 `checkpoint_path` 时会 `model.load_peft_model(checkpoint_path)`，用于在已有 LoRA 上继续训

## 训练流程（`main.py`）

1. `model, tokenizer = init_model(checkpoint_path=...)`
2. 配置 `SwanLabCallback(...)`（项目名/实验名/配置字典）
3. SFT（可选）
   - `load_dataset("unsloth/OpenMathReasoning-mini", split="cot")`
   - `format_sft_dataset(...)`
   - `train_sft(...)`
   - `model.save_pretrained("sft_saved_lora")`
   - 清理显存：`torch.cuda.empty_cache()` + `gc.collect()`
4. GRPO（可选）
   - `load_dataset("open-r1/DAPO-Math-17k-Processed", "en", split="train")`
   - `format_grpo_dataset(...)`
   - 计算 `max_prompt_length` 与 `max_completion_length`
   - `train_grpo(...)`
   - `model.save_pretrained(checkpoint_path)`（默认在 `__main__` 里传了 `../grpo_saved_lora`）

## 运行方式（最小）

在该目录下直接运行：

```bash
python main.py
```

如果你想仅跑其中一个阶段，修改 `__main__` 里的 `main(run_sft=..., run_grpo=..., checkpoint_path=...)` 参数即可（当前代码没有 argparse/CLI 参数解析）。

## 常见坑与扩展点

- 输出标记强绑定：GRPO 的奖励函数硬编码依赖 `<结束推理> / <答案> / <答案结束>` 这几个标记；如果你改了 `config.py` 的标记文字，务必同步 `train_grpo.py` 里的常量或改为从 `config` 统一导入。
- `SWANLAB_API_KEY` 不应写死在仓库：`config.py` 当前直接设置了 key。建议改成读取外部环境变量并在本地注入，避免泄露与误提交。
- 数据子集选择：`select(range(5))` 只会训练 5 条样本，适合 smoke test，不适合实际训练。
- 模型路径写死：`../../../models/Qwen3-4B` 依赖本地目录布局；更通用的做法是改为可配置参数或环境变量。
